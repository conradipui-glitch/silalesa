# Контекстный и сезонный первый экран «Сила Леса» (пилот)

## Что готово
- Главный оффер сайта — **«Строительные работы в Омске»**. Отдельные работы названы первыми, строительство под ключ остаётся в перечне.
- 14 проверенных параметров `?service=` изменяют только H1, лид и CTA на главной странице. Примеры:
  - `/silalesa/?service=monolith` — монолит.
  - `/silalesa/?service=plaster` — машинная штукатурка.
  - `/silalesa/?service=roofing` — кровля.
- Переходы можно использовать в рассылке, рекламе и QR-ссылках, если услуга и ожидание пользователя совпадают. Аналитика CTA помечает `offerMode` и `service`; канал/конверсию необходимо проверять в реально настроенной аналитике.
- `referrer`, скрытый поисковый запрос, IP, геолокация и user-agent для персонализации не используются. Это предотвращает неправильные догадки и не меняет контент специально для роботов.
- Canonical, title, description, OG и статический HTML **не переключаются сезонно**. Открытые через органику страницы услуг `/mehanizirovannaya-shtukaturka-omsk/` и `/polusuhaya-styazhka-omsk/` остаются отдельными посадочными с уникальным содержанием; создавать SEO-дубли ради `?service` не следует.

## Сезонное правило сейчас не включено
Файл `src/data/seasonal-demand.json` содержит `verified:false` и пустые `leaderByMonth`. Прямой заход в октябре, марте и другие месяцы показывает нейтральный оффер, **пока статистика не получена и не проверена**.

Инструмент GSC Wizard временно возвращает `payment_required`, поэтому значения не получены и не заменены оценками. Кроме того, GSC сообщает *результат текущей видимости нашего сайта*, а не полный рыночный спрос. Для сравнения направлений используем Яндекс Вордстат с выбором **Омской области**, запросами за два завершённых календарных года, детализацией **по месяцам**, без смешения типов устройств и точными сопоставимыми фразами. Вордстат требует авторизации: https://wordstat.yandex.ru/.

## Сбор данных
Для каждого из 14 направлений:
1. Выбрать **одну устойчивую коммерческую формулировку** с географией и одинаковой логикой точного соответствия, а не суммировать пересекающиеся широкие запросы. Зафиксировать исходную строку и оператор поиска.
2. Скачать CSV с помесячными значениями для Омской области из Яндекс Вордстата за два *полных* года (например, 2024 и 2025 в 2026 году). По возможности сохранить исходные экспорты вне публичного GitHub.
3. Свести значения в одну таблицу UTF-8 CSV с заголовком **строго** `month,service,queries,region,phrase`. Пример формата, **не пример реального спроса**:

```csv
month,service,queries,region,phrase
2024-01,monolith,<указать-реальное-целое-число>,Омская область,монолитные работы омск
```

Вместо плейсхолдера должно быть целое фактическое значение; подготовить 12 месяцев × 14 направлений × 2 года = **336 строк** (для каждого направления одинаковая phrase во всех месяцах). Дополнительные месяцы допускаются, но компилятор выбирает два последних завершённых года.

Поддерживаемые коды: `cottages`, `monolith`, `masonry`, `plaster`, `screed`, `concrete-screed`, `topping`, `metalworks`, `hangars`, `multistory`, `buildings`, `demolition`, `roofing`, `facades`.

4. После ручной проверки пары «термин ↔ услуга» и исходных экспортов:

```bash
node scripts/compile-seasonal-demand.mjs /path/to/reviewed-omsk.csv --evidence-ref=wordstat-oms-2024-2025 --dry-run
```

Компилятор выбирает направление с максимумом среднего месячного спроса за два года, **только если** оно превышает второе минимум на 20% и средний объём не меньше 20 запросов/месяц. Если данные близки, он оставляет общий оффер. Это **пилотные пороги**, а не объективная бизнес-модель.

Затем команда без `--dry-run` перезаписывает `src/data/seasonal-demand.json`; опубликовать её можно только после ревью исходных цифр, семантики и пригодности услуги к выполнению. Не смешивать данные Московской области, РФ и Омска.

## Что нужно ещё проверить до запуска автоматического сезона
- Спрос по Wordstat ≠ количество коммерческих заявок и тем более ≠ прибыль компании. Сопоставить с подтверждёнными обращениями, доступностью бригад и экономикой маржи.
- «Монолит», «полы», «штукатурка» требуют разных вариантов коммерческих запросов; сравнивать только широкие фразы некорректно.
- Доля Google/Yandex, отказы и заявки в Метрике или GA4 пока не подтверждены; отчёты GSC Wizard не доступны из-за подписки.
- Утверждённый сайт не должен рекламировать сезонную услугу, если в этот период её не могут выполнять.
- После включения сезонности проверять 12 месяцев в автоматизированных тестах, сравнивать CTR/контактные клики для прямых заходов и явно помеченных кампаний, а не объявлять повышение конверсии без эксперимента.

## Почему не менять H1 на произвольный скрытый запрос
Поисковые системы обычно не передают органическую фразу в HTTP referrer. Использование разных SEO-текстов только для краулеров и посетителей — риск deceptive cloaking. Поэтому меняется только легальный, выбранный из белого списка фокус по ссылке, а не «угадывается» источник. Базовый контент сайта остаётся доступным всем.
