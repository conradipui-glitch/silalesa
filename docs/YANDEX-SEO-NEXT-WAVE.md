## Почему не переписываем всё немедленно

- Для 4 ремонтных статей уже настроены уникальные Title/Description, смысловые H2, FAQ, Article JSON-LD, внутренняя перелинковка и первый ответ. Менять их снова до анализа эффективности рискованно.
- `yaai` подтвердил выбранные формулировки спроса на кровлю, стяжку и фасады, но **не** передал метрики обращения → договор и реальную коммерческую конверсию по страницам.
- **Решение владельца:** Яндекс.Метрику не подключаем до согласования сайта с заказчиком и переноса на домен в зоне `.ru`. Отсутствие счётчика на GitHub Pages не является ошибкой этой итерации. Клики по каналу связи = намерение, не реальная заявка.
- Для кровли и фасадов не хватает утверждённых коммерческих условий, собственных подтверждённых кейсов и фактов о возможностях бригад.

## Граница между согласованием и аналитикой

**Текущий этап:** согласование контента и функциональности с заказчиком на GitHub Pages. SEO-исследования через `yaai`/Wordstat/SERP, проверки текстов, фактов, коммерческой готовности, техническое SEO и ручной учёт реальных обращений доступны уже сейчас; **не требовать Яндекс.Метрику** и не оценивать конверсию без данных.

**После согласования:** переезд на согласованный `.ru`-домен с проверкой редиректов, canonical, sitemap, robots.txt, региональности и индексации. **Только после проверки домена** — отдельная задача на Метрику и цели с учётом согласия/политики конфиденциальности. Повторный SEO-аудит статей не нужно откладывать только из-за отсутствия счётчика: ограничить выводы тем, что действительно известно.

## Триггер для следующей партии статей

Проверяем перед PR:

1. Из `yaai` и/или Вебмастера получена **страница → поисковая фраза → показы/клики/CTR/позиция** для главного региона; либо честно помечено, что доступ отсутствует, а решение основано на SERP и спросе, без заявлений об эффективности.
2. Для каждого информационного интента сохранены примеры текущей выдачи Яндекса, отделены вопросы от коммерческих запросов и от банной семантики, исключено создание дубля существующей коммерческой услуги.
3. Есть подтверждённый список реальных условий компании для связанного CTA; фотографии «до/после» описываются как объекты компании только при подтверждённом происхождении. Не писать искусственно подробные оговорки «это иллюстрация» в каждом тексте; при необходимости сделать ненавязчивую единообразную пометку рядом с изображением.
4. Рядом со страницей есть конкретное действие — запрос расчёта или переход к существующей услуге; работать оно должно на мобильном и без JS.
5. После согласованной публикации сравниваем одинаковые интервалы показа/CTR/конверсии с учётом сезонности, а не объявляем SEO-рост только потому, что файлы обновились.

## Приоритет следующей волны

| Этап | Страницы | Какой интент проверять |
|---|---|---|
| 1 | Коммерческая `/polusuhaya-styazhka-omsk/` + связанные гайды по стяжке | Цена за м², условия расчёта, устройство основания, трещины как отдельный вопрос |
| 2 | Информационные гайды о ремонте, штукатурке и последовательности отделки | Полнота ответа, отсутствие ключевого переспама, разделение тем с коммерческими страницами |
| 3 | Статьи о банях и выборе моделей | Кластеры выбора, комплектации, доставки, установки, сравнение фактических цен и реальных изображений — только по соответствующему спросу |
| 4 | Индексируемые посадочные по кровле и фасадам | **Только после** подтверждения специализаций и доказательств компании; `/brief/roofing/` и `/brief/facades/` — noindex-микространицы соцсетей и не должны служить заменой SEO-страниц |

Для каждого URL: исходный смысл → проверенные запросы и потребность → H1/первый ответ/H2/FAQ → рабочая перелинковка → контекстный CTA → Title/Description/canonical/OG/JSON-LD/no-JS → Playwright/mobile → GitHub Pages. Править **2–4 статьи за волну**, не сотни сразу.

Не применять: покупные SEO-ссылки, накрутку поведения, клоакинг, массовый шаблонный SEO-текст, вымышленные отзывы и обещания. Особое внимание: региональность, полезность первого экрана, коммерческие условия и мобильное удобство.

Утверждения скилла о сравнительных весах факторов не являются публично раскрытыми формулами Яндекса; решения опираются на собственные показатели, официальную документацию и проверяемую выдачу.
