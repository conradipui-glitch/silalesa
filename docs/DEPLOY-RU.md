# Сила Леса — подготовка к размещению на российском хостинге

## Одно место для цен и статусов
`src/data/commercialRegistry.json`: 14 направлений каталога плюс отдельная существующая SEO-страница бурения скважин (историческая структура). Статусы: `primary` (основное), `consultation` (по согласованию), `paused` (новые обращения временно не принимаются). При `paused`: карточка отсутствует в каталоге, статическая страница остаётся по исходному адресу с `noindex, follow` и отсутствием кнопки заказа, URL убирается из sitemap. При возврате в active состояние страница снова участвует в sitemap.

Менять цену на двух калькуляторах только через `priceFrom` соответствующих `plaster` и `screed`. Команда `npm run build` синхронизирует математические константы, SEO-манифест и статические страницы; перед коммитом изменённых ставок зафиксировать синхронизированные исходники и при необходимости обновить связанные статьи/прайсы.

## Два режима сборки
- **GitHub Pages (демо):** `GITHUB_PAGES=true npm run build`. Preview origin указан в `config/site.json`.
- **Боевой корневой домен:** `SITE_TARGET=production SITE_ORIGIN=https://ВАШ-ДОМЕН.ru npm run build`. Не использовать выдуманный адрес: требуется подтверждённый домен владельца. Результат — `dist/` с корневыми путями, каноническими URL, метатегами, sitemap и robots. Отсутствие настоящего `SITE_ORIGIN` завершает сборку ошибкой.

Перед загрузкой на Timeweb подтвердить владение доменом, выбрать тариф, проверить веб-сервер, каталог сайта, SSL, доступность `/services/`, обеих страниц калькуляторов и внутренних SEO-страниц, правильную отдачу 404. На Apache файл `public/.htaccess` задаёт `ErrorDocument 404 /404.html`, не перенаправляет несуществующие URL на главную. Для Nginx конфигурация сервера на стороне хостера должна поддерживать `/slug/index.html` и реальный HTTP 404. Нельзя считать `.htaccess` универсальным решением для Nginx.

## Шрифты
`public/fonts/`: локальные WOFF2 для кириллицы и латиницы. Проверить в Network отсутствие запросов к `fonts.googleapis.com` и `fonts.gstatic.com`. Лицензии приложены.

## Яндекс Метрика
`VITE_YM_COUNTER_ID=<номер>` в окружении сборки — после выдачи счётчика заказчиком. При отсутствии номера скрипт не подгружается. Рекомендуемые JavaScript-цели в интерфейсе Метрики: `calc_interact`, `calc_complete`, `tel_click`, `messenger_click`, `lead_intent`. Нужна проверка отправки в DebugView/консоли и рабочей сети. Клик по MAX, копирование карточки и открытие формы не являются доказательством полученного или подтверждённого заказа. Не использовать внутренние UTM.

## Контакты и персональные данные
Сайт готовит текст, отправку пользователь подтверждает самостоятельно. Обезличенные карточки для исполнителя не включают телефон, e-mail, адрес и имена помещений. Пересылка контактных данных исполнителям должна иметь законное основание и отражаться в соответствующей политике обработки персональных данных. Политика и необходимые согласия заполняются фактическими реквизитами оператора до включения сбора ПДн; сама локализация шрифтов не означает автоматическое соответствие 152-ФЗ.

## Историческое банное направление
Банные маршруты исключены из индексируемого sitemap и реестра активных направлений; архивные исходники пока сохранены для истории. Эта итерация гарантирует изоляцию **публичных маршрутов и контента HTML**, и удаление устаревших банных изображений из собранного `dist/assets` посредством `scripts/prune-archived-assets.mjs`. Архивный TypeScript/JavaScript-код и неиспользуемые строки могут сохраняться в чанках — их окончательное удаление потребует отдельного рефакторинга и тестирования. Полную чистку tree-shaking/архивного бандла следует делать отдельной технической задачей с регрессионным тестированием.

## Передача заказчику
Регистрация домена и хостинга — на клиента и за его счёт напрямую провайдеру. Дальнейшая платная поддержка не обязательна, новые задачи — только по отдельному согласованию. Мини-админка не входит в стоимость базового сайта.
