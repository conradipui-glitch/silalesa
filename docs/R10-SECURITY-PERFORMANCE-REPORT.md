# R10 — устранение предупреждений зависимостей и оптимизация загрузки

Дата диагностики: 22.09.2026 UTC. Изменения в `fix/r10-security-speed-images`. Этот отчёт описывает техническую часть R10; окончательная ручная приёмка остаётся открытой в `docs/R10-ACCEPTANCE-REPORT.md`.

## Безопасность зависимостей

Проверка исходного `package-lock.json` командой `npm audit --json` обнаружила **2 проблемы: low и high**. Уязвимы инструменты сборки и разработки, а не доказанно опубликованный статический сайт:

- `esbuild@0.27.7`: low, `GHSA-g7r4-m6w7-qqqr` (dev-сервер, Windows).
- `vite@7.3.2`: high, `GHSA-fx2h-pf6j-xcff` (dev-сервер, Windows); аудит также показывал связанный с Vite advisory `GHSA-v6wh-96g9-6wx3`.

Проведено адресное обновление до `vite@7.3.6` и `esbuild@0.28.2` с синхронизацией `package.json` и `package-lock.json`. Применён только обычный `npm audit fix`, **без `--force`** и без смены major-версий. После чистого `npm ci`: `npm audit --audit-level=low` сообщает **0 уязвимостей** на момент проверки. В `.github/workflows/ci.yml` добавлен обязательный аудит, чтобы новые находки блокировали CI; это не гарантия отсутствия будущих advisories. Логи: GitHub Actions R10 diagnostics `35771739276`, финальная проверка с обработкой фотографий `35774178826`.

## JavaScript: исправлена причина предупреждения, порог Vite не повышали

| Показатель | До | После |
|---|---:|---:|
| Начальный JS (`index-*.js`, до gzip) | 708 409 Б | 354 551 Б |
| Начальный JS после gzip | 176,20 КБ | 104,34 КБ |
| Отдельный модуль SEO-данных | Внутри начального JS | 241,45 КБ, gzip 49,09 КБ |
| Отдельный модуль SEO-страниц | Внутри начального JS | 108,96 КБ, gzip 23,71 КБ |

Реальное разделение выполнено через `React.lazy`/`Suspense`: код SEO-страниц и полный реестр длинных гайдов загружаются при переходе к этим страницам, не на главной. Для начального маршрутизатора, ссылок на модели и мобильного CTA из тех же исходных SEO-данных автоматически генерируется компактный `routeManifest.ts`; `npm run build` отклоняет устаревший манифест. Начальный JS уменьшился примерно на 50% до gzip и на 41% после gzip. **Предупреждение Vite о блоке свыше 500 КБ исчезло; `chunkSizeWarningLimit` не меняли.** Важно: SEO-страницы при открытии требуют отдельные JS-запросы; сумма всех чанков не тождественна загрузке главной. Лог реальной сборки: run `35773651683`.

## Фотографии: проверены именно опубликованные ресурсы, а не все исходники Git

Сопоставлены исходные файлы и итоговая директория `dist/assets`. Крупные JPG-оригиналы, не попавшие в `dist`, не являются весом загрузки пользователя; они сохранены как исходники. Все 14 реально публикуемых фото до исправлений весили **3 106 685 Б**, после — **2 340 240 Б**: экономия **766 445 Б (~24,7%)** по сумме ресурсов, а не обещание ускорения конкретного устройства.

## Постоянные защиты и ограничения

- `scripts/check-r10-performance.mjs` включён в стандартный `npm run build`: бюджет начального JS менее 400 КБ, отдельные SEO-чанки, главная фотография менее 230 КБ, общий опубликованный объём фотографий менее 2,85 МБ. Проверка изображения — вес, а не визуальное утверждение о безупречном качестве.
- `.github/workflows/ci.yml` включает `npm audit --audit-level=low`; для маршрутов и фото продолжают выполняться все регрессии R1–R10.
- `.github/workflows/r10-browser-smoke.yml` проверяет Chromium на настольном размере и **эмуляции мобильного экрана**: загрузку страниц, реальное декодирование главного фото, отложенные SEO-чанки и адрес WhatsApp **без отправки сообщения**. Результат запуска указывается после PR-проверки; эмуляция не заменяет реальный телефон.
- Lighthouse/Web Vitals, LCP в полевых условиях и фактическая скорость у посетителей **не измерены**; цифры выше — воспроизводимые размеры файлов и результаты сборки. Ручное подтверждение фотографий и полный чек-лист владельца остаются открытыми до фактической приёмки.
